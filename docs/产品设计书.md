## 1. 产品概述

日记本是一款本地优先的 Windows 桌面程序，包含日记和待办两个模块。

日记模块用于快速记录、按日期浏览和搜索个人内容。待办模块用于记录有截止日期的事项，并按紧急程度展示。程序不登录、不联网也能完整使用，用户数据默认只保存在本机。

MVP 的判断标准不是功能数量，而是用户能否稳定完成三个动作：

1. 随手写下日记，并在下次打开时找回。
2. 按日期或关键词找到过去的内容。
3. 记录待办及其 DDL，快速判断哪件事最紧急。

## 2. 目标用户

MVP 面向单机个人用户，主要特征如下：

- 希望日记保存在本机，不把私人内容上传到第三方服务。
- 需要同时记录日记和简单待办。
- 不需要团队协作、复杂项目管理或跨设备同步。
- 更看重记录速度、数据安全和长期可用性，而不是编辑器功能。

## 3. 产品目标

### 3.1 MVP 目标

- 日记内容可以创建、编辑、保存和重新打开。
- 日记可以按日期浏览，并支持标题和正文搜索。
- 待办可以设置 DDL、编辑、完成和删除。
- 未完成待办始终按 DDL 先后排列。
- 当日、临近和已过期的待办可以快速区分。
- 全程离线可用，数据持久化到本机。
- 核心排序、日期和数据持久化逻辑有自动化测试。

### 3.2 非目标

以下内容不进入 MVP：

- 账号、登录、会员和云同步。
- 手机端、网页端和多设备同步。
- 图片、音频、视频和文件附件。
- 富文本、复杂排版、表格和嵌入内容。
- 系统通知、后台常驻和定时提醒。
- 重复待办、子任务、优先级、标签和拖动排序。
- AI 摘要、AI 写作和情绪分析。
- 插件系统、主题商店和社交分享。
- 密码锁和端到端加密。

这些功能会扩大数据迁移、权限、网络、打包和测试成本，不与 MVP 的核心验证目标直接相关。

## 4. 信息架构

程序使用两个一级模块，不设置首页或仪表盘。

### 4.1 日记

- 左侧：日记列表、日期筛选和搜索入口。
- 右侧：日记编辑器。
- 新建日记后直接进入编辑器。
- 点击列表项后切换当前日记。

### 4.2 待办

- 左侧：月历和筛选入口。
- 右侧：待办列表。
- 列表顶部提供新建入口。
- 默认展示“全部未完成”，点击某日期后切换为当天筛选。

“功能区”统一命名为“待办”。不要使用含义过宽的栏目名，避免后续功能继续堆入该区域。

## 5. 核心使用流程

### 5.1 写日记

1. 用户进入“日记”。
2. 点击“新建日记”。
3. 系统创建包含当前日期、空标题和空正文的记录。
4. 用户输入标题和正文。
5. 系统自动保存，并显示保存状态。
6. 用户关闭程序后重新打开，内容仍然存在。

### 5.2 查找日记

1. 用户进入“日记”。
2. 用户选择日期，或输入搜索关键词。
3. 系统展示匹配的日记列表。
4. 用户点击结果并查看或继续编辑正文。
5. 清空筛选后恢复默认时间排序。

### 5.3 新建待办

1. 用户进入“待办”。
2. 用户点击“新建待办”。
3. 用户填写事项名称并选择 DDL 日期。
4. 系统保存待办，并把它插入正确的排序位置。
5. 用户可以编辑、完成或删除该待办。

### 5.4 处理待办

1. 用户打开“待办”，默认看到全部未完成事项。
2. 过期事项和今天到期事项具有不同状态标识。
3. 用户完成事项后，它从主列表移入“已完成”区域。
4. 用户取消完成后，事项按原排序规则回到未完成列表。

## 6. 功能需求

### 6.1 日记增删改查

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| D-01 | 新建日记 | 使用当前本地日期作为默认记录日期 |
| D-02 | 编辑日记 | 支持标题和正文；标题可以为空 |
| D-03 | 自动保存 | 输入停止后自动保存，切换日记或关闭窗口前再次保存 |
| D-04 | 保存状态 | 明确显示“保存中”“已保存”“保存失败” |
| D-05 | 删除日记 | 删除前二次确认；确认后删除当前记录 |
| D-06 | 重复记录 | 同一天允许存在多篇日记 |
| D-07 | 正文格式 | MVP 使用纯文本；保留换行，不渲染富文本或 Markdown |
| D-08 | 修改日期 | 编辑页允许修改日记所属日期 |

保存失败时不得伪装为已保存。窗口关闭前存在未保存内容时，应阻止直接关闭并提供重试或放弃选项。

### 6.2 日记列表与日期浏览

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| D-09 | 默认排序 | 按日记日期倒序；同一天按创建时间倒序 |
| D-10 | 列表摘要 | 展示日期、标题和正文摘要 |
| D-11 | 日期筛选 | 选择日期后只显示该日期的日记 |
| D-12 | 清除筛选 | 提供返回全部日记的明确入口 |
| D-13 | 空状态 | 无日记、日期无结果时展示对应提示和新建入口 |
| D-14 | 当前项 | 当前打开的日记在列表中保持可见且状态明确 |

### 6.3 日记搜索

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| D-15 | 搜索范围 | 同时匹配标题和正文 |
| D-16 | 搜索行为 | 输入关键词后即时或短延迟过滤，不要求点击提交 |
| D-17 | 组合筛选 | 搜索可与日期筛选组合使用 |
| D-18 | 结果排序 | 搜索结果继续按日期倒序排列 |
| D-19 | 无结果 | 显示无匹配内容，不自动创建新日记 |

MVP 使用本地包含匹配即可，不引入模糊搜索、分词服务或独立全文索引。

### 6.4 待办管理

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| T-01 | 新建待办 | 事项名称必填，DDL 日期必填 |
| T-02 | 编辑待办 | 可以修改事项名称和 DDL 日期 |
| T-03 | 完成待办 | 支持标记完成和取消完成 |
| T-04 | 删除待办 | 删除前二次确认 |
| T-05 | 默认排序 | 未完成优先，按 DDL 升序 |
| T-06 | 同日排序 | DDL 相同时按创建时间升序 |
| T-07 | 已完成排序 | 已完成事项位于底部，按完成时间倒序 |
| T-08 | 日期状态 | 区分“已过期”“今天到期”“未来到期” |
| T-09 | 空状态 | 无待办时展示说明和新建入口 |
| T-10 | 完成区域 | 已完成事项默认折叠，可展开查看 |

待办名称最长长度、DDL 可选范围和标题换行规则需要在技术方案中统一限制，避免 UI 被超长文本破坏。

### 6.5 待办日历

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| T-11 | 月历展示 | 默认显示当前月份 |
| T-12 | 日期标记 | 有未完成待办的日期显示标记 |
| T-13 | 日期筛选 | 点击日期后只显示当天到期的待办 |
| T-14 | 返回全部 | 提供“全部未完成”入口，清除日期筛选 |
| T-15 | 月份切换 | 支持查看上个月和下个月 |
| T-16 | 今日定位 | 支持快速回到今天所在月份和日期 |

日历选择只影响待办列表筛选，不改变日记模块的状态。

## 7. 业务规则

### 7.1 日期规则

- 日记日期和待办 DDL 都使用用户的本地日期。
- 日期存储格式使用 `YYYY-MM-DD`，不保存 UTC 时间戳后再换算。
- “今天”“已过期”的判断以程序运行时的本地日期为准。
- 待办在 DDL 当天仍属于今天到期，不算过期。

### 7.2 排序规则

日记默认排序：

```text
entry_date 倒序
→ created_at 倒序
```

待办默认排序：

```text
未完成优先
→ due_date 升序
→ created_at 升序
→ 已完成按 completed_at 倒序
```

排序规则必须封装为独立逻辑并覆盖边界测试。

### 7.3 删除规则

- 删除操作必须二次确认。
- 删除后无法在 MVP 内恢复。
- 确认框中显示被删除内容的标题或名称，降低误删概率。
- 不做自动清空数据，不因搜索无结果删除内容。

## 8. 数据模型

以下为概念模型，具体字段类型以技术方案为准。推荐使用 SQLite 作为本地存储。

### 8.1 日记 Entry

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| id | 唯一标识 | 必填 |
| entry_date | 日记所属日期 | `YYYY-MM-DD`，必填 |
| title | 标题 | 可空 |
| content | 正文 | 可空，保留换行 |
| created_at | 创建时间 | 必填 |
| updated_at | 最后修改时间 | 必填 |

### 8.2 待办 Todo

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| id | 唯一标识 | 必填 |
| title | 事项名称 | 必填 |
| due_date | DDL 日期 | `YYYY-MM-DD`，必填 |
| completed | 完成状态 | 必填，默认未完成 |
| completed_at | 完成时间 | 未完成时为空 |
| created_at | 创建时间 | 必填 |
| updated_at | 最后修改时间 | 必填 |

建议索引：

- `entries(entry_date DESC, created_at DESC)`
- `todos(completed ASC, due_date ASC, created_at ASC)`
- `todos(completed_at DESC)`

## 9. 界面状态与反馈

### 9.1 通用状态

- 首次无数据：展示功能说明和主要操作按钮。
- 加载数据：避免界面闪烁，并防止重复提交。
- 操作成功：列表、编辑区或状态文字立即更新。
- 操作失败：展示可理解的错误信息和重试入口。
- 数据冲突或保存失败：保留用户当前输入，不静默覆盖。

### 9.2 待办视觉状态

| 状态 | 条件 | 表现建议 |
| --- | --- | --- |
| 已过期 | `due_date < 今天` 且未完成 | 使用高辨识度警示色 |
| 今天到期 | `due_date = 今天` 且未完成 | 使用强调色或“今天”标签 |
| 未来到期 | `due_date > 今天` 且未完成 | 使用普通状态 |
| 已完成 | `completed = true` | 弱化显示，移入折叠区域 |

颜色不能作为唯一状态信息，必须同时使用文字或图标。

## 10. 非功能需求

### 10.1 离线与隐私

- 首次启动和日常使用均不要求网络。
- 不上传日记、待办或用户行为数据。
- 不接入遥测服务。
- 网络不可用时，所有核心功能保持正常。

### 10.2 数据完整性

- 每次保存使用完整事务，避免半写入状态。
- 程序崩溃或强制关闭后，最近一次明确显示“已保存”的内容不得丢失。
- 自动保存失败时必须保留编辑区内容，并允许用户重试或复制文本。
- 数据库损坏或无法读取时，不自动覆盖原文件。

### 10.3 可用性

- 从打开程序到开始输入日记，不经过多余确认步骤。
- 新建日记、保存和搜索应保持键盘可操作。
- 中文日期、中文标题和中文正文必须正确显示和搜索。
- 删除、完成、取消完成等状态变化应立即反馈。

### 10.4 兼容性

- MVP 以 Windows 10 和 Windows 11 为目标。
- 高分屏下文字和控件不得明显模糊或错位。
- 窗口缩放后编辑区和列表仍可使用。

## 11. 验收标准

### 11.1 日记

- 新建日记并输入标题和正文后，可以自动保存。
- 关闭并重新打开程序后，日记内容、日期和标题保持不变。
- 同一天可以创建多篇日记。
- 列表按日期倒序展示，同日记录顺序稳定。
- 选择日期后只显示对应记录，清除筛选后恢复全部记录。
- 搜索标题或正文中的关键词，可以找到对应日记。
- 搜索与日期筛选组合后结果正确。
- 删除日记前必须确认，取消确认时不删除。
- 保存失败时界面不显示“已保存”，输入内容不丢失。

### 11.2 待办

- 新建待办时必须填写名称和 DDL。
- 默认列表按未完成、DDL、创建时间排序。
- 同一天创建的多个待办顺序稳定。
- 过期、今天到期和未来到期状态正确。
- 完成待办后，事项进入已完成区域。
- 取消完成后，事项回到正确的未完成排序位置。
- 编辑 DDL 后，事项立即移动到正确位置。
- 删除待办前必须确认。
- 点击日历日期后，只显示该日期到期的待办。
- 点击“全部未完成”后，清除日期筛选。
- 没有待办或筛选无结果时展示正确空状态。

### 11.3 边界情况

- 当天的待办不计为过期。
- 跨月、跨年和闰年日期排序正确。
- 标题或正文为空时程序不崩溃。
- 超长标题和正文不会破坏窗口布局。
- 系统日期发生变化后，“今天”和“已过期”状态重新计算。
- 连续快速输入时，不因自动保存导致内容倒序或丢失。

## 12. 测试要求

### 12.1 自动化测试

- 日记增删改查及持久化。
- 日记默认排序和搜索结果排序。
- 待办增删改查、完成状态和恢复未完成。
- 待办排序：过期、今天、未来、同日、已完成。
- 日期解析、跨月、跨年和闰年。
- 搜索标题、正文、空关键词和无结果。
- 自动保存成功、失败和重试。

### 12.2 集成与手工验证

- 关闭并重启后数据仍然存在。
- 保存过程中切换日记不会串写内容。
- 删除确认和取消行为正确。
- 日历筛选和列表状态一致。
- 处理中英文混排、长文本和高分屏显示。
- 断网环境下完整执行所有流程。

每次代码改动完成后，必须更新受影响测试并确保全部测试通过。无法自动化验证的桌面交互，需要在提交前完成手工检查并记录结果。

## 13. 成功指标

MVP 不接入遥测，使用本人连续使用结果判断：

- 能在 1 分钟内完成第一次日记创建和保存。
- 能在 10 秒内创建一条带 DDL 的待办。
- 连续使用 7 天，不发生日记或待办数据丢失。
- 能通过列表、日期和搜索找回任意一篇测试日记。
- 待办列表无需手动整理，即可看出最紧急事项。

## 14. 版本规划

- 标题、正文和待办名称的长度限制。
